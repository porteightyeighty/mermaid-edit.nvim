1. INTRODUCTION                                       *mermaid-edit-introduction*

mermaid-edit.nvim performs structural edits on mermaid flowcharts using the
tree-sitter parse tree: insert a step between two nodes, swap adjacent steps,
change a node's shape, restyle an edge, and label edges. It rewrites the shared
node ids that connect a linear chart so the chain stays intact.

==============================================================================
2. REQUIREMENTS                                       *mermaid-edit-requirements*

- Neovim 0.10+
- The `mermaid` tree-sitter parser (e.g. `:TSInstall mermaid`).

Run `:checkhealth mermaid-edit`.

==============================================================================
3. SETUP                                                     *mermaid-edit-setup*

                                                          *mermaid-edit.setup()*
>lua
    require("mermaid-edit").setup({
      keymaps = {
        insert_step  = "<leader>mi",
        add_step     = "<leader>mo",
        swap_down    = "<leader>mj",
        swap_up      = "<leader>mk",
        change_shape = "<leader>ms",
        change_arrow = "<leader>ma",
        edit_label   = "<leader>ml",
        remove_node  = "<leader>md",
      },
      default_shape = "square",
    })
<
Set any keymap entry, or `keymaps` itself, to `false` to disable. With
lazy.nvim, `opts = {}` calls setup for you.

==============================================================================
4. COMMANDS                                               *mermaid-edit-commands*

:MermaidInsertStep              Insert a new step between the two nodes on the
                                edge under the cursor. Prompts for a label.

:MermaidAddStep                 Add a step after the node under the cursor as a
                                new outgoing edge. On a terminal node it extends
                                the chain; on a node that already has a successor
                                it forks off a new branch. Prompts for a label.

:MermaidSwapDown                Swap the step on this line with the next step.

:MermaidSwapUp                  Swap the step on this line with the previous
                                step.

:MermaidShape                   Change the shape of the node under the cursor
                                (pick from a list).

:MermaidArrow                   Change the arrow style of the edge under the
                                cursor (pick from a list, e.g. -->, ---, -.->,
                                ==>, --o, --x). Any edge label is kept.

:MermaidLabel                   Add, edit, or remove the label on the edge under
                                the cursor (`A -->|label| B`). The prompt is
                                prefilled with the current label; submitting an
                                empty label removes it.

:MermaidRemove                  Remove the node under the cursor and bridge the
                                gap: each predecessor is reconnected to each
                                successor so the chain stays connected. On a
                                one-liner or `&` branch the node is spliced out
                                in place.

The commands always work regardless of the keymap configuration.

==============================================================================
5. MAPPINGS                                               *mermaid-edit-mappings*

Buffer-local in `mermaid` buffers (defaults):

  <leader>mi      :MermaidInsertStep
  <leader>mo      :MermaidAddStep
  <leader>mj      :MermaidSwapDown
  <leader>mk      :MermaidSwapUp
  <leader>ms      :MermaidShape
  <leader>ma      :MermaidArrow
  <leader>ml      :MermaidLabel
  <leader>md      :MermaidRemove

==============================================================================
6. LIMITATIONS                                         *mermaid-edit-limitations*

- All flowchart connectivity is handled: one edge per line
  (`SRC <arrow> TGT[label]`), chained one-liners (`A --> B --> C`), and `&`
  branching - fan-out (`A --> B & C`) and fan-in (`A & B --> C`). Multi-line
  branches stay connected through a swap because the diagram is re-threaded by id
  and the connecting edge is located by id, not adjacency. On a one-liner or `&`
  line, swap reorders in place and insert splices into the transition under the
  cursor; reshape reaches any vertex, including inside an `&` group. Subgraphs
  are out of scope.
- Write parseable mermaid. A few constructs are valid mermaid that the grammar
  still errors on, and mermaid-edit refuses to edit a tree with errors:
  - Use `<br>`, not `<br/>` (the self-closing slash makes the grammar error;
    `<br>` renders identically).
  - Use the dotted arrow `-.->`, not the dotted open link `-.-` (the grammar
    can't parse `-.-`, so the arrow picker omits it). Fix an existing `-.-` to
    `-.->` by hand once and editing works again.
